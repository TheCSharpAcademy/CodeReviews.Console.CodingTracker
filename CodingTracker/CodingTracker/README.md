
# Coding Tracker Project

This project is a coding tracker based on requirements from The C# Academy. It allows a user to track their coding sessions, which are then added to a database. The user can decide between entering the details manually or using a timer to track their sessions This database can be read from and its data can be displayed. Added coding sessions can be removed and updated by the user. 

## How to Run the Project

This project uses several exteral libraries and extensions for styling console text and creating tables, reading data, mapping objects to database entries and allowing the execution of sql commands.

To install these dependencies use these commands in the projects folder accessed in the terminal:

- 'dotnet add package Spectre.Console' - Used for styling console text and creating tables.
- 'dotnet add package Microsoft.Data.Sqlite' - Allows the use of sql commands and database connection
- 'dotnet add package Dapper' - The ORM. This maps database entries to objects.
- 'dotnet add package Microsoft.Extensions.Configuration' - This allows us to read JSON files.

## How it Works

On starting the app the user will be presented with a title and a list of options including: 'Start Coding Session', 'Manage Coding Sessions' and 'Exit'.

### Start Coding Session
On selecting this option the user will be asked to confirm that they wish to start tracking a coding session. If the enters 'n', then they will be returned to the previous menu, else they will be prompted to choose between tracking a session manually or using a timer. Choosing the 'Manual' option will prompt the user to enter the date and time for the start and end of the coding session. If a user selects 'AutoTimer', a timer will begin and will end when the user presses 'Enter'. Once a session has been completed and entered the user is asked to confirm that they wish to store it in the tracker.

### Manage Coding Sessions
On selecting this option the user will be prompted with another menu with several options including: 'View All Sessions', "Delete Session", "Update Session" and 'Exit'.

#### View All Sessions:
Selecting this option will prompt the user to select whether they wish to view all sessions in ascending or descending order. Once selected a table with all sessions will be printed based on the preivous input.

#### Delete Session:
Selecting this option will prompt the user to select the ID of the session they wish to delete. Once selected the user will be asked to confirm that they wish to delete this session. If the user enters 'n' then they are returned to the preivous menu. Else the session will be deleted and a confirmation message will appear.

#### Update Session:
Selecting this option will prompt the user to select the ID of the session they wish to update. Once selected, more prompts will appear asking the user to enter the 'start time' as well as the 'end time' for the session. Once entered correctly the user will be asked to confirm if they wish to update the session. If they decline they will be returned to the preivous menu. Else the session will be updated and a confirmation message will appear.

#### Exit to Main Menu
Selection this option will return the user to the main menu.

### Exit

On selecting this option a message will appear thanking the user for using the application. They will be prompted to press 'Enter' and the app will subsequently close.

## The Creation Process

The first feature I decided to tackle was to create a main menu for the user to land on when launching the app. This was done using a switch statement inside a Run() method in my controller class and the user input is gathered from the GetMainMenuInput() method inside of my UI class. Separating these two was necessary to adhere to SRP (or Single Responsibility Principle). Each class would handle its own related tasks. No functionality was added just yet, besides the ability to exit the app with the 'Exit' option.

Next it was necessary to create a database file to read from and write to. To do this I created a new class called DatabaseInitialiser. This file uses 2 external libraries: Dapper and Microsoft.Data.Sqlite. Before writing the code to initialse my database I needed to create a JSON file that would store my connection string. To read from this, it was necessary to create a new class called ConfigReader. This file contains one method called ReadConfig(). This method reads from the database and gets the connection string, returning it when called. With this created it was now time to finish initialsing my database. I now create a string that calls the ConfigReader() method, using it as the connectionString. I then execute an sql command using Dapper that creates a table called CodingSessions if one does not exist already. When this is executed, a database file is created automatically. Both reading the config file and using database commands are very susceptible to issues so I felt it was necessary to use exception handling to ensure a clean exit from the app should a problem occur. The database is initialised once the app starts running.

The next step was to allow the user to add a CodingSession to the database. To do this I created a CodingSession class. Each CodingSession object requires an ID, StartTime, EndTime and a Duration. In my CodingSessionRepository class I created a method called AddCodingSession(). This method attempts to connect to a database, therefore I used try-catch blocks to ensure a clean exit should an error occur. First I create my sql command text and a connection string (aqcuired by calling the ReadConfig() method). I creat the connection using my connection string and open the connection. I then execute my sql command and pass in a CodingSessionObject. In my UserInput class I created a method called GetDateTime which takes a string as parameter that alters text depending on if it is the start or end time that is required. The user is prompted to input the date and time of the session, it is validated and returned. I also created some methods to prompt the user for confirmation, print an error message and to prompt the user to press enter to confirm. Back in CodingTrackerController I created a method called StartCodingSession(). This uses the confirm message mentioned earlier to ask the user if they are sure they wish to start a session. The GetDateTime() method is called to get both the startDate and endDate of the CodingSession. A check is also run to ensure that endDate is greater than startDate. If it is not then then an error is printed. A new CodingSession is created based on this input. Duration is calculated by removing the startDate from the endDate and then using the TotalHours and Minutes properties. The user is asked to confirm via a prompt that they wish to enter this CodingSession to the database. If they accept then the session is added by passing it to the AddCodingSession() method.

I then decided to create the functionality to allow the user to view all currently added sessions in the database. To do this I created a ManageSessions() method in my Controller class. This is also a menu so it uses a loop. Before adding the ViewAllSessions()
method I created another method inside CodingSessionRepository called GetAllSesssions(). I create a List that will contain CodingSession objects. Like before I create the sql command, connect to the database and this time i use a different method to map the each session row to CodingSession objects, and then add them to the List, using Dapper. This method returns the List of CodingSession objects. To print the table I created a new TablePrinter class in my UI folder. This contains a PrintSessionsTable() method that takes in a List of CodingSession objects as a parameter. A check is run on the passed List to ensure that it is not empty. If it is the user is returned to the previous menu. If the List is not empty a table is created with its columns. The List is looped over and a row is created for every CodingSession. The table is then printed. Back in the ViewAllSessions() method, the PrintSessionTable is called with the GetAllSesssions() method passed as a parameter. To access this option, and future 'Manage Coding Session'options, from the menu I created a GetManageSessionMenuOption() method in UserInput. This prompts the user to select a menu option.

Next came the option to delete a session from the database. In my CodingSessionRepository I created another method called GetAllSesssionIds() which was resonsible for returning a List of all CodingSession IDs currently stored in the database using Dapper to execute the command. Also in this class I created a DeleteSessionFromId() method which takes an int as its parameter. This int will be the Id that is passed to the method for deletion. This connects to the database like the previous methods but this time uses paramterised input (the Id) to execute the sql deletion command. In my UserInput class I created a method called GetCodingSessionIdInput(). This prompts the user to select an Id based on the passed List<int>. Back in my Controller class I create a DeleteSession() method. This creates a List<int> calling the GetAllSesssionIds() method for its values. The session Id, that will be deleted, is aqcuired by calling the GetCodingSessionIdInput() method with the list of session ids passed as a parameter. The user is asked to confirm that they wish to delete the session from the database and if so the ExecuteSessionDeletion() method is called. Inside this method DeleteSessionFromId() is called with the Id passes as a parameter. Originally this was done using one method, however I separated them to ensure my app follows SRP. At this point I also decided to include a GoodBye() method in my UserInput class which prints a message when called in the Program class. This is called on exiting the app.

For updating a session I decided to refactor how I validate the startTime and endTime. I created a new method called GetValidatedSessionTimeFrame(). This returnes the startTime, endTime and duration values. This method will only stop running when the user enters the dates for both entries in the correct format and if the starting time is not greater than the end time. This method is used in StartCodingSession() to ensure that there is no duplicate code, following the DRY Principle (Dont Repeat Yourself). Another helper method I decided to add to my Controller class was MapToCodingSession() which handles the creation of new variables based on duration (totalHours, minutes). It returns a new CodingSession object. I created another method called GetCodingSessionUpdateInput() which takes in a CodingSession (that is to be updated). This method calls the GetValidatedSessionTimeFrame() method and returns the validated input by calling MapToCodingSession() with the start time, end time, duration and session ID passed as parameters. In the UpdateSession() method I first create a List<int> that calls GetAllSessionIds(). This is passed to GetCodingSessionIdInput() to get the Id of the object the user wishes to update. A new CodingSession object is created that gets its value by calling the GetSessionFromId() method, (a method inside the CodingSessionRepository class. That queries the database and returns a session from a parameterised Id). The UpdateSessionFromId() method takes an id, and a CodingSession as parameters. It behaves like the DeleteSessionFromId() method, this time using a command to update a row in the database. Back in the Controller class I created an UpdateSession() method that creates a List<int> of ids using the GetAllSessionIds() method. An Id is collected using GetCodingSessionIdInput(), passing the List<CodingSession> as a parameter. A CodingSession object is created using GetSessionFromId() and passing the Id as a parameter. A new CodingSession object is created using the GetCodingSessionUpdateInput() method, passsing the preivous CodingSession object as a parameter. If the user confirms that they wish to update this session then ExecuteUpdateSession() is called, using the id, and the updated session as a parameter. 

With the main CRUD operations completed I decided it was necessary to create seed data for the database. With data already added the user will be able to use all menu operations from the moment the app starts. In my DatabaseInitialiser class I created a new method called SeedData() which takes an SqliteConnection as a parameter(which allows us to use the connection from the InitialiseDatabase() method). A check is run to ensure that there is data to read from and if not the method is exited. A list of new CodingSession objects is created and are used to query the database using paramterised values. This method is called at the end of the InitialiseDatabase() method. It was at this point I decided to alter the ViewAllSessions() method to require a List<CodingSession> parameter. This allows me to pass the List of sessions and ensure that there are sessions to print using a check. I added this check to UpdateSession() and DeleteSession()

Next I decided to add styling to the app using Spectre Console features. I added colour to text to make it stand out, ensuring that the prompts, column names, error messages and confirmation messages are clearer to the user. I also added a Figlet to the main menu for aesthetic purposes. 

An issue that remained was when a user selects 'Start Coding Session' and enters 'n' at the prompt, the user is brought to the main menu, however the figlet is printed twice. I could not use spectre console in the Controller class as that would violate SRP, however I created a class called ClearDisplay() in the UserInput class. This method is called in the Controller class instead. I then decided to add confirmation messages to each action the user interacts with when altering the database to ensure that they can change their mind or correct a mistake.

An extra feature I decided to include in the application was the ability for the user to sort the coding sessions table. To do this I created an enum called SortOrderOptions. It contained the values 'Ascending' and 'Descending'. In the UserInput class I created a new method called GetOrderOption(). This prompts the user to select one of the enum values which will then be used to sort the table. In the TablePrinter class I created a SortSessions() method that takes a List<CodingSession> and a SortOrderOptions enum value. If the enum value is 'Ascending' then the list is ordered by ascending using LINQ operations. Else it is ordered by Descending.

The final feature I decided to implement was the ability to track a session using a timer. The user would be able to select the option, upon which the timer starts. It then awaits further user input to stop the timer and creates a CodingSessionObject based on the tracked information. To allow the user to select which type they wish to use to track their session I first created an Enum called TrackingType that contained two values: 'Manual' and 'AutoTimer'. In the UserInput class I created a GetTrackingType() method that prompts the user to select between the two TrackingType values. I also created two other methods: DisplayMessage() and AwaitUserInput() which were responsible for displaying a message to the user (in this case to prompt the user to press enter when they wish to complete the tracking of the session) as well as allowing the user to press 'Enter' to complete the session. Back in the Controller class I altered the StartCodingSession() method to include these new methods and the code to track the session using a timer.

After completing the project requirements I decided to make one small adjustment after some testing. The table was being sorted by the StartTime of a CodingSession, however if two or more sessions happen to occur on the same day they may not be in the right order. To fix this issue I decided to use the EndTime of a CodingSession for this case.

## Key Takeaways

Overall I found this project quite enjoyable and it tested my coding ability. My first experience with the ORM, or in this case the micro ORM, Dapper has been very positive. I came to understand the usefulness of ORMS in mapping objects to database elements and found it incredibly intuitive to use. I look forward to using Dapper or other ORMS in future projects. At the beginning of this project I felt somewhat confused as to how to properly separate the concerns of my code. Upon further research I gained greater understanding of the benefits of SRP and how to properly implement it. I now feel more confident in applying it to future projects.
